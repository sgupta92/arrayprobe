# 3. Validation

**What it is for.** Deciding whether a result can be trusted: comparing a product with a
reference, checking an engine against a flight whose true particles are known, and scoring a
hypothesis in a way no one can quietly adjust afterwards.

**Who it is for.** Anyone about to quote a number, and anyone comparing their own run with an
archived or independently produced product.

**Order.**

1. `01_validate_against_a_product`: the comparison function, first on demo data (both denominators, where a real residual lives, tolerance classes), then on two files you supply by editing a single cell.
2. `02_known_truth`: a synthetic flight with every droplet and fragment known, run through the engines, with recovered over true concentration per size band.
3. `03_preregistered_test`: a hypothesis, statistic and pass rule written down and hashed before the data exist, then scored with a seeded bootstrap.

**What you need.** Found by reading each notebook's code cells. Run from the repository root.

| Notebook | Beyond the core package | Data |
|---|---|---|
| `01_validate_against_a_product` | `scripts/make_demo_flight` and `make_demo_reference` | Demo flights generated, plus shipped `tests/data` fixtures. The final section needs **two product files you supply** (`OURS`, `REFERENCE`, both `None` until you set them). One optional section reads a cut of real records from the validation campaign, not distributed with the package; it is skipped with a message unless that cut is present |
| `02_known_truth` | `scripts/truth_harness`; runs the v3.5 and SODA-2 chains | Known-truth flight generated by `synthetic_truth` |
| `03_preregistered_test` | None | A stand-in product (`base200101000000.combined.H.2DS_2.cdf`) generated in the notebook; writes `registration.json` |
