# All-enhancements-on sets, per probe and engine
> Generated from `arrayprobe_enhancements.registry`, `arrayprobe_enhancements.applicability` and the per-probe restriction table the driver computes these sets with; never hand-typed. Rebuilt by the documentation build.

What a run gets when every enhancement in [`arrayprobe_enhancements`](https://github.com/sgupta92/arrayprobe/blob/main/enhancements_uiops/src/arrayprobe_enhancements/registry.py) is switched on, for each of four probes (2D-S, HVPS, CIP, PIP) on the UIOOPS v3.5 engine. SODA-2 is covered separately in §5 -- it has no engine axis and no per-probe registry.

**Probe applicability is not enforced anywhere in the resolver.** `arrayprobe_enhancements.applicability` gates by engine only; the probe restrictions below are read off each module's own `registry.py` summary and the `PROTECTIVE` probetype table ([`registry.py:750-757`](https://github.com/sgupta92/arrayprobe/blob/main/enhancements_uiops/src/arrayprobe_enhancements/registry.py)), not measured by a runtime check. CIP and PIP are probetype 1, read from `constants.IMGPROC_CONFIG` (`imgProc_sm.m:138-156`).

**See also** [Enhancements](05-enhancements.md) · [Which enhancements apply to which engine](23-enhancements-by-engine.md) · [Enhancements by stage](25-enhancements-by-stage.md) · [Probes](33-probes.md).

## 5. SODA-2

SODA-2 has its own package, [`arrayprobe_soda2_enhancements`](https://github.com/sgupta92/arrayprobe/blob/main/enhancements_soda2/src/arrayprobe_soda2_enhancements/registry.py), with a per-module registry. It differs from the UIOOPS registry on two axes: **no engine matrix** (SODA-2 has one source tree, so there is nothing for an `applicability`-shaped module to consult), and **no archived-product lineage**: SODA-2 has written no archived product for any probe, so its `PROTECTIVE` set (the corrections for data-destroying upstream defects) runs by default on every probe, per the protective-corrections rule, and a config opts *out* by name or with `--protective off`. Every other correction is opt-in, as on the UIOOPS side.
